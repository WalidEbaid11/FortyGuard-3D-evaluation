Summary · 14 November 2026

Can a new customer go from zero to an alert?

Yes, but with real friction in the first hour. Tested on New York (Brooklyn, Queens) and Phoenix, from Windows, using the Dashboard, Python, the MCP server (Claude Code and the official Python SDK) and n8n.

The data itself

Street-level variation a city forecast cannot show: about 3 °C between Brooklyn and eastern Queens. Reproducible across every surface.

A clean async model

Submit, receive an activity ID, poll. An MCP that states every paid call’s cost and asks for confirmation first.

Structured errors

Code, offending field and a retriable flag. Every MCP response carries a trace with cost and latency.

1 · Temperature Dashboard

Instantly convincing, unevenly polished

What worked

  • Demo map shows value at once: 13.38 °C in Brooklyn vs 10.21 °C in eastern Queens.
  • Tile, Information, Actions (Capture, Environmental Parameters, Heat Intelligence) is intuitive.
  • Settings offer Metric, Imperial and Custom units.

Friction

  • Imperial applied to temperature only: wind stayed 18.52 m/s next to 57.13 °F.
  • Heat Index, Cloud Cover, Precipitation have no units.
  • UV Index and Air Quality show “null (Low)” and “null (Good)”.
  • Toast reads “Sucessfully”; panel talks about “heating systems”.

2 · Heat Intelligence report and Selesious AI

Broad reports, a brilliant agent, shaky numbers

Report: strengths

Seconds to generate. Five analysis areas, table of contents, satellite figures and sources per section.

Report: contradictions

The tile says 13.52 °C, the text cites 33.5 °F and calls the value an artifact. Prospect Park is 585 and 526 acres. Impervious surface: 70–85%, 80–90%, 65–75%.

Selesious: great

Point temperature matched the map (55.9 °F). Top 5 of 23,824 tiles, hottest 60.4 °F, with segmentation: 56% buildings, 15% roads, 27% trees.

Selesious: issues

Apparent temp 0.5 °C and wet-bulb 2.1 °C beside 13.3 °C air at 62% humidity. Wind “unavailable” though the map shows it. “155.9 °F” for 55.9 °F.

Coverage not reported

At 100 m the grid covered about 60% of the requested area (390 m cut west, 190 m south) with no warning.

Inconsistent limits

granularity=20 works on REST, but the MCP schema allows only 60, 80, 100 and does not say so.

Thin results

No unit field, no tile centre, identical min/avg/max per tile, a two-bin histogram, no completed_at.

Docs

Quickstart stops at “Completed”. “Enterprise API” vs “Temperature API” naming.

4 · Temperature MCP

Agent-friendly by design, with a billing hole

Setup

Claude Code connected first try: 11 tools, labelled read-only, open-world or destructive. A paid plan was needed, so tool tests ran through the official Python SDK.

Strengths

Costs in tool descriptions, confirmation prompts, idempotency_key, trace with cost and latency. Cairo returned OUT_OF_COVERAGE, retriable=false, no charge.

Billing without a response

env_params failed twice (“SSE stream ended without a response”). Balance: 949,360 → 942,240 → 939,340. No trace ID to quote.

Schema and docs gaps

11 tools vs 9 documented. env_params needs the temperature as input. Celsius vs Fahrenheit across tools. Swapped streetview angles.

Agent limits

heatmap_read returns stats only, not where the hottest spot is. monitoring mixes read and delete, so everything is labelled destructive.

6 · Recommendations

What I would fix first

Make the first run succeed

Fix the quickstart, define coverage per polygon, name the rejected field and allowed values.

Be consistent

Same parameters, limits and units on Dashboard, REST and MCP. A unit field everywhere. One product name.

Describe what you returned

Requested vs covered area with a warning, tile centres, compact output, completed_at.

Protect credits

No billing without a response, early trace ID, REST idempotency, documented refunds.

Serve automation users

Webhook callbacks, webhook alerts for monitors, an n8n node or template, top-N hottest tiles in MCP, split monitoring tools.

Tidy the Dashboard

Summer demo date, validate the report’s temperature input, label every unit, remove “null”.

Where AI comes in next

Automation now, intelligence on top

The MCP exposes the same capabilities to AI agents. The natural next step is an AI node that turns each run’s statistics into a plain-language advisory. It is not part of this demo.
